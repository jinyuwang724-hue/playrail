# 任务：验证并修复各种场景下的窗口切换稳定性

## 背景
- 项目同上。此记录的基线是游戏库 0.1.243 和 ClawShell 1.0.9（保留 explorer，任务栏隐藏）。后端 0.17.58 为就地热补丁（原始文件在 `.claude/worktrees/bold-jennings-a19012/artifacts/qp/agent-0.17.58-orig/`）。 [早期交接记录](../../docs/archive/toolbox-2026-10/CLAUDE_HANDOFF.md)
- 窗口切换入口：快捷面板（QAM）的「窗口切换」卡片，以及特殊键长按。游戏库在游戏模式里充当窗口管理器（不用 SetParent 嵌入）。
- 已做的：切换前 dismiss 开始菜单 / 搜索，重试 3 次，失败退回游戏库。窗口化《鸣潮》（常规脱离）与 Claude Code 之间压测 120/120 成功，每次约 250 ms。
- 已知问题：1.0.9 保留 explorer 时任务栏工作区没有释放，最大化窗口只到 y=1176，游戏库会把窗口重新铺满。
- 用户之前的现象：全屏游戏时从游戏切到 Claude Code 失败；有开始菜单时唤出切换器会空屏、无法切换（后者在 0.1.243 已修，需回归）。

## 没覆盖到、这次要测的场景
1. 独占全屏游戏（不是无边框）。找一款支持独占全屏的游戏，或者用 D3D11/D3D12 独占全屏的小测试程序。测：唤出快捷面板、切到其他窗口、再切回游戏。看是否黑屏、分辨率闪变、游戏最小化后回不来、面板被游戏盖住。
2. 管理员权限运行的游戏或程序（UIPI 会挡 SetForegroundWindow / 输入注入）。
3. 文件管理器（explorer 窗口，和 shell 是同一进程）作为切换源和目标。
4. 物理特殊键：短按打开面板，长按打开切换器，各 30 次。确认长按不会同时触发游戏库（已知 bug：快设键有时也会唤出 Claw 游戏库，属于按键串扰）。
5. 真机手指从底边上滑后马上切换（和任务 1 的边缘滑动禁用一起回归）。
6. 回归：在系统设置页面开始菜单弹出时唤出切换器，不应空屏。
7. 混合压测：上述窗口各开一个，随机顺序切换 200 次，记录成功率、耗时 P50/P95、失败时的前台窗口和错误码。

## 要做的
- 给切换路径加结构化日志（目标 hwnd、进程、是否独占全屏、是否提权、每一步耗时与结果）。
- 按测试结果修复。可能的方向（实测后再定）：
  - 独占全屏先发 Alt+Enter 或改用最小化，或者提示游戏改为无边框；
  - 提权进程由后端（已有管理员能力）代为切前台；
  - 用 AllowSetForegroundWindow / AttachThreadInput；
  - 修复 y=1176 工作区问题（游戏模式下正确设置 SPI_SETWORKAREA，回到桌面时还原）。
- 失败兜底仍然回游戏库，不允许停在空屏。
