# 游戏模式窗口管理：前端常驻与窗口切换器（2026-11-03）

安装：游戏库 **0.1.201.0**（由 0.1.200 原位升级，偏好未变），ClawShell **1.0.2**，后台仍为 0.17.58。

## 做法

游戏模式 = 关掉 explorer，没有任务栏和桌面。所以由两层一起保证「总有游戏库窗口、它不会停在最小化」：

- **ClawShell 监视进程（watch / shell）**，每秒一次：游戏库进程不在就重新激活（带 `--game-shell`）；进程在但窗口不可见或最小化，就给窗口发 `game-shell` / `keep-game-shell` 消息让它显示（不抢前台）。60 秒内失败 3 次才退回桌面。
- **游戏库自己**（`MainWindow.GameShell.cs`，每 0.5 秒）：刚进游戏模式时拉到前台；窗口被最小化或隐藏就原样放回（停在前台窗口后面）；前台没有任何应用窗口（游戏关了、别的窗口都最小化了）1 秒后自己回到前台。游戏模式下关窗口、「退出游戏库」、最小化都改成停在游戏后面，不会真的关掉或进托盘。
- **窗口切换器**沿用 0.1.197 的：游戏模式下长按特殊键直接打开独立切换器（也在控制中心「窗口」页）。列表含最小化的窗口，A 切过去时先还原。

## 1.0.2 修的问题

0.1.200 的监视进程把「进程在、窗口还没出来」当成一次失败，并立刻再激活。游戏库崩溃重启、冷启动、切桌面时窗口都要几秒才出现，连续三次就会被误判成崩溃循环、退回桌面（11-02 01:17 切桌面时日志里就有一次误判）。开机时没在 3 秒内抢到前台也算失败。

现在：窗口未就绪先等 10 秒宽限，期间每秒继续请它显示；宽限过后才算失败。开机进程和窗口都在、只是没抢到前台，不再算失败，交给监视继续看着。外壳测试 42 + 14 项通过（新增 3 项）。

## 实机验收（`tools/Test-GameShell201.ps1`，结果 `artifacts/game-shell-201/acceptance.json`）

切到游戏模式后逐项，最后自动切回桌面：

| 情况 | 结果 |
| --- | --- |
| 进入游戏模式，游戏库在前台 | 62 ms |
| 游戏库被外部最小化 → 恢复可见 | 228 ms |
| 打开再关掉一个窗口 → 游戏库在前台 | 30 ms |
| 另一个窗口最小化 → 游戏库在前台 | 22 ms |
| 切换器路由打开，列出 4 个窗口（含最小化的测试窗口） | 通过 |
| 强杀游戏库 → 监视进程重新拉起、仍在游戏模式 | 0.9 s |

没测到：测试窗口没抢到前台（系统前台锁），所以「关掉前台应用」这一项实际是游戏库本来就在前台；真实游戏的退出、特殊键实体长按都没在这一轮按。

## 0.1.203：左侧栏、窗口管理器、动画（同日）

- **左侧栏盖在窗口上唤出时整屏变黑、游戏库像没了**：以前面板底下铺纯黑，只把窗口画面贴在面板右边。游戏模式下游戏库本来就垫在窗口后面，现在底下照样是游戏库（压暗），窗口画面原位原尺寸，不挪不缩。录帧见 `artifacts/game-shell-201/burst2open|close`。
- **唤出后游戏库被收走、回到上一个程序**：日志里快设打开面板 38 ms 后，紧跟着来了一次游戏库开关，把面板连库一起收到后面。现在每个路由都记日志，游戏模式下快设之后 600 ms 内的游戏库开关不理（`route … ignored`）。
- **窗口管理器换回控制中心「窗口」页**：0.1.197 的长按是单独一张黑底、一下子出现。现在长按 = 控制中心从游戏库卡形变出来再进「窗口」页，背景是控制中心的动态背景。B 回到唤出前的地方：在游戏库上唤出的形变回墙；盖在程序上唤出的，那个程序按原位淡回来。A 切窗口：卡片沉下去、选中的窗口原位淡进来再切过去。快设面板里的「窗口切换」走同一条路，面板滑出、游戏画面淡掉。
- 新增 `Stage/WallStage.WindowReveal.cs`：用 DWM 实时画面在窗口原位淡入 / 淡出，所有「回到某个窗口」「盖到某个窗口上」都走它。
