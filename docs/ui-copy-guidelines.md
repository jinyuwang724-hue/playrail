# UI 文案克制与自解释设计规范

2026-10-29 定。适用于游戏库、控制中心、快捷面板、OOBE、Game Bar 小组件和所有设计稿。

遵循极简、功能优先、视觉自解释的设计原则，严格控制界面中的非必要文字。

1. 默认精简文案：不主动添加 slogan、欢迎语、营销式修辞、教学段落、装饰性副标题及重复性辅助说明。
2. 结构优先于解释：优先通过布局、视觉层级、分组、留白、图标及交互状态传达信息，而非使用文字解释界面。
3. 避免文案堆叠：不为每个标题、卡片、功能区或按钮机械性地添加描述文字。
4. 保留必要信息：仅在影响用户理解、操作、决策或错误恢复时显示辅助文案。
5. 渐进式信息披露：非关键、低频解释优先使用 Tooltip、Popover 等按需展示方式；关键提示、风险警告和必要操作说明应直接可见。
6. 禁止填充式设计：不要为了填补空白、增强所谓的设计感或营造高级氛围而添加无实际信息价值的文字。

核心原则：每一段可见文案都必须有明确的信息价值。能够通过设计表达的内容，不再使用文字重复解释。

## 落到手柄界面上

- 只有图标的控件，焦点落上去时浮出名字（Popover）。不常驻文字标签。
- 数值、单位、当前选项属于信息，可以直接显示。分区标题旁边那种重复下方数值的摘要（比如「手动 · 25 W」）不加。
- 左栏图标已经标明分区，右侧就不再重复写分区标题。
- 风险操作（关机、重启、恢复出厂、改固件）的确认文字直接显示，不藏进 Popover。
