# 游戏库原生版：对照与实测（2026-10-14，MSI Claw 8，1920×1200 @150%，60 Hz）

代码在 `frontend/library-native/`。WinUI 3 只做窗口，墙面全部画在 Microsoft.UI.Composition 视觉层上，
相机 / 缝 / 让位 / 翻牌 / 波次动画都在合成线程跑；NativeAOT，自包含 MSIX，用 CN=ClawToolbox 签名。

## 实测

- 冷启动（AOT MSIX，封面缓存已生成）：进程启动 → 第一帧 483–640 ms（中位约 525 ms），屏上封面全部解码约 0.75–1.0 s
- 首次启动另需约 10–11 s 在后台从 Steam 原图生成封面套件（期间墙正常显示，封面逐张出现）
- 帧间隔（`bench.json`，DWM 合成时间戳）：右摇杆平移、十字键走位、展开 / 收起、换页签波次、进出合集全部 p99 = 16.67 ms（60 Hz 每帧都到）；整轮只有 1 个 33 ms 帧
- CPU：静止 0.05–0.2 %，动画中 1–2.3 %（占全部核心）；GPU 3D：静止 0 %，动画中 2–5 %
- 内存：启动后工作集约 210 MB（私有 155 MB），来回翻几个页签后约 340 MB（封面缓存）

## 与网页版的差别

- 集合信息条的「共 N 小时」读的是本机 Steam 时长（网页版没读，显示 0）
- 「Narcissu 1st & 2nd」显示 &（网页版把 `&amp;` 原样显示了）
- 新的让位不会把上一次没走完的卡冻在半路（网页版快速连按时会）
- 颗粒噪点是近似（网页是 soft-light 混合）；边缘标签没有滑入动画；鼠标悬停效果没做
- 启动游戏仍是占位提示（与网页版相同）

## 2026-10-14 第二轮：动态背景与可交互竖条

**背景**：去掉了颗粒噪点（之前用随机噪点拉伸近似 soft-light，放大后成了斑点）。改成参照 folia 首页墙后面那层 visualizer
（「common」模式）的机制自己实现：底色 + 15 个缓慢漂移、自转的几何形（圆 / 方 / 三角 / 叉，七成描边三成实心，
不透明度 11–19 %，30–60 s 一圈）+ 20 个往上飘的光点 + 暗角；颜色取自当前焦点游戏的主色。墙是实色的，缝是 folia 的
「始终透明」材质（底色 64 % 的纱、上沿淡渐变、两侧发丝线），背景从缝里透出来。全是合成线程的循环动画；
缝合上、窗口不在前台、60 秒没操作、关掉动态背景或降低动态效果时暂停（原地冻住）。

**竖条**（首页窄缝 120 px，从上到下）：时间 + 电池 → 竖排页签（放不下全名时缩成一个字，再放不下在里面滚）→
分隔线 → 合集直达入口（竖排短列并排）→ 头像 + Windows 用户显示名 → 搜索 / 设置 / 文件管理器。LB/RB 提示去掉了。
- 焦点能进竖条：墙上横着走、下一张跨过缝时进竖条，落在离那张卡最近的一项；竖条里上下按行走、左右出竖条回到墙上
  那一侧离得最近的卡。焦点在竖条里时那一项白色描边高亮，墙上的焦点环熄掉。B 先关设置 / 搜索，再回墙上。
- 页签：A 换页签（整墙波次）；合集入口：A 打开合集；头像：打开 Windows「你的信息」；文件管理器：打开资源管理器。
- 设置（竖条里展开）：标题样式、动态背景、降低动态效果、性能读数。
- 搜索：竖条里出一个输入框（XAML TextBox，支持中文输入法），按名字过滤当前页签，墙翻牌换成结果。
- 鼠标点竖条里的项同样生效。

截图：`rail-focus.jpg`（焦点在竖条的账户项上）、`rail-settings.jpg`（设置展开）。

**实测（AOT MSIX）**：`bench-rail-backdrop.json`——走位、平移、展开 / 收起、换页签、进出合集全程每帧 16.7 ms，
整轮只有 2 帧 33 ms。静止时动态背景在动：CPU 约 0.7 %、GPU 3D 约 1.3 %；60 秒无操作后暂停：CPU 0.03 %、GPU 0 %。
（只有缝里那一条在动时 DWM 会隔帧合成，约 8 % 的帧 33 ms；角落加一个 1 px 一直在动的点后每帧准时，背景暂停时它也停。）

## 2026-10-14 第三轮：放大 / 缩小时封面错位、「隐现」背景

**封面错位**：原因有两个——展开 / 收起一开始卡面就按终点重建，图直接换成终点要用的那一种（竖封面 ⇄ 大背景方裁），
取景也是终点的；动画结束时又按新尺寸重新请求一张图，新图异步解码，中间有空白帧、取景跳一下。现在：
- 卡面重建时先原样接着画正在显示的那张图、同样的取景（第一帧和变之前一模一样）；
- 取景跟着卡片的让位弹簧走（每一刻都按那一刻的宽高比算）；
- 要换成另一种图时，新图叠在旧图上、解码好之后在剩下的时间里淡入；同一张图要更高分辨率时，新的解码好才换。
- 所有有让位动画的卡（展开那张和同一块里让位的其它卡）都走这一套。截图：`expand-frames.jpg`、`collapse-frames.jpg`（连拍）。

**「隐现」背景**：一比一移植 folia 的 Latent 背景（`Shaders/Latent.hlsl`）：Paper Shaders 0.0.80（Apache-2.0）的
MeshGradient 与 Dithering 片元着色器数学 + folia LatentBackground 的叠法与默认参数（流体速度 0.3 / 扭曲 0.8 / 旋涡 0.1 /
颗粒 0.01；像素层 warp / 4x4 / 格子 2.5 / 速度 0.1 / soft-light 0.55；主题底色遮罩 35 %；流体层 scale 1.025 +
saturate 1.04 + brightness 0.94，像素层 scale 1.015）；颜色是焦点游戏竖封面 50×50 的加权中位切分 6 色（folia colorPalette）。
画布分辨率同 folia（总像素 ≤ 1280×720），每帧只算缝的开口那一条。截图：`latent-seam.jpg`。
与 folia 的差别：folia 主页默认让它静止，这里让它动；换焦点颜色 800 ms 渐变；墙面在动（相机、让位、翻牌、波次、平移）
时背景停帧（时钟也停），动完接着走——两者同时出帧会让 DWM 隔帧；60 秒无操作暂停。

**实测（AOT MSIX）**：`bench-latent.json`——整轮约 35 秒只有 12 帧 33 ms（其余 16.7 ms）。静止时背景在动：
CPU 0.8 %、GPU 3D 1.9 %；60 秒无操作后 CPU 0.04 %、GPU 0 %。

## 2026-10-14 第五轮：正中取景、整个 Steam 库、安装、背景断层

- **封面从正中裁**：横图、方图、没有竖封面时的兜底竖图都从正中取景，不再按种子清单里的焦点（艾尔登法环以前只剩边角）。封面套件版本升到 3，旧套件第一次启动时在后台重做（约 35 秒，按墙上顺序，先看得到的先做）。
- **整个 Steam 库**：`appcache\librarycache` 下的 appid（Steam 给库里每一项缓存的封面目录）+ `appcache\appinfo.vdf`（v28 / v29 二进制 KeyValues）里的名字、类型、开发商、发行年份。只要类型是游戏的；用户自己放进分类里的软件（比如「工具」里的 Wallpaper Engine）也收。Steam 里「已隐藏」的不上墙。本机：371 项 → 179 款上墙（27 款隐藏）。
- **装没装**：各个库目录（`libraryfolders.vdf`）里 `appmanifest_*.acf` 的 StateFlags 带完整安装位。没装的卡上角标写「STEAM · 未安装」，展开后按钮写「安装」。
- **A 键**：装好的走 `steam://rungameid/<appid>`；没装的走 `steam://install/<appid>`（Steam 弹出安装窗口，按一下就开始下载）；本地游戏是 Steam 里的非 Steam 快捷方式，用 `(appid << 32) | 0x02000000` 的游戏 ID 启动。
- **分类**：减掉 `removed` 里的游戏；一款游戏都没有的分类不显示（本机的「收藏夹」「甜蜜女友」）。
- **背景断层**：以前背景钉在屏幕上、只画缝的开口那一条；墙面平移时背景停帧，缝挪到的新位置露出很久以前画的旧画面（时间和颜色都不同），就是那道断层。现在画布按「缝在首页的位置」来画，整块视觉用表达式跟着缝平移（合成线程上，不用重画）；缝变宽时画布中心往正中靠，铺满全屏时正好是整张画布。换色渐变按出帧的时间走，停帧时渐变也停，不会一下跳色。
  - 试过墙面动的时候背景也照常出帧：DWM 隔帧合成，平移 / 展开 / 换页从 60 掉到 51–57 fps（126 帧慢帧），所以保留「墙面动时背景停一下」。现在停的只是它自己极慢的流动，整块仍跟着缝走。实测（停帧版）：各段 60 fps，只有展开 / 收起有 8 帧慢帧。

## 2026-10-14 第六轮：进合集时竖条背景的断层

- 原因：墙面在动时背景整帧停画。进合集时缝从竖条张到合集页的宽度，这段动画里两边新露出来的画布一直没画（是建画布时清成的底色，或者很久以前画的旧画面），动画结束才补上，于是两边一条断层、再跳回来。
- 修法：墙面在动时背景的流动和换色照样停（不推进时间），但开口变宽 / 挪动时，**只补画新露出来的那两头**（记下画布上已经是「此刻」的那段，停帧期间画面时间不变，补出来的和原来的严丝合缝）；补间途中的开口宽度按相机起止两头和开口终点取最宽的。开口变化不再整条重画，背景停着时开口变了也会唤起一帧去补。
- 实测：今天这台机器的帧数整体比下午低（同一时刻把上一次提交单独编译对照，展开 / 收起同样是 51 fps），这次改动前后数字一致，没有带来额外的慢帧；补画只在开口变宽的那一帧发生，整个跑分里一共二十几次。
