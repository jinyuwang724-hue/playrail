## 功能与数据流

1. `claw_game_session.py` 统一游戏身份和生命周期，综合 Game Bar 的目标信息、游戏库启动提示、已有 Steam 快捷方式目标，以及前台呈现行为。用 PID 与创建时间共同标识会话。
2. `GameTarget.h` 定期读取 Game Bar 官方目标跟踪信息，实际运行中确认目标跟踪可用。后台通过目标 HWND 解析程序；对 ApplicationFrameHost 外层窗口查找 CoreWindow 的实际所属进程。
3. `claw_power.py` 将采集与 RTSS 绘制拆开，发布结构化监控快照。首页、监控与 AutoTDP 共用游戏会话；旧游戏数据不会转用于新会话。
4. 现有 Game Bar 控制面板的性能显示磁贴改为专用 OSD 接口。切换显示档位不会因为提交整个旧设置快照而重写功耗、风扇设置。
5. `OsdPage` 是同安装包中的独立监控组件，支持关／1—4 档、字号、单双行、缩小单位、自定义显示项目／顺序／颜色／透明度，以及逐帧时间曲线。
6. RTSS 绘制保留为可选兼容方式。全局只选择一个绘制方式；现有限帧功能仍单独依赖 RTSS。

游戏识别没有预置测试程序或逐款支持名单。少量“视为游戏／忽略／恢复自动识别”纠正按完整路径保存，并要求操作目标的会话身份仍有效。

## 本机必须补上的 PresentMon 回退

本机的 Intel PresentMon Shared Service 2.5.1 能打开会话、注册查询、跟踪进程，但测试程序的完整显示链路查询一直返回零值。C# 与直接调用官方 C API 的独立诊断均复现。具体驱动／显示链路原因尚未确定。

同机官方 PresentMon 控制台在关闭显示完成／GPU／输入跟踪、仅采集 CPU Present 事件时能获得有效逐帧样本。因此新增 `claw_presentmon.py`：

- 共享服务连续三次没有有效帧样本后，自动启动针对当前进程的独立 ETW 采集。
- 使用 `ClawToolboxOSD-<后台PID>` 专用会话名，不停止其他软件的跟踪会话。
- 在采集失败、目标切换、关闭 OSD 且不需要 AutoTDP 采样、或后台退出时释放自己的采集。子进程另有 60 秒上限，避免后台异常退出后无限驻留。
- CSV 样本按进程、交换链分开，缓冲有上限；旧样本会过期。曲线使用实际测得的逐帧间隔，不从平均 FPS 反推。
- 这条回退得到的是“呈现帧率”，界面明确这样标注。它不能确定插帧来源，因而不提供 `appFps` 给 AutoTDP；缺少真实渲染帧率时智能功耗保持等待。

完整旧 `power_backend_test.py` 在风扇平滑部分有一处已有断言失败；已用未修改的基线源码复现，记录为基线失败。现有手柄页 NativeAOT／裁剪警告和缺少符号打包工具警告仍存在，两个安装包构建成功。

接口测试还发现诊断代理会将临时端口／口令写入正式小组件的连接文件；现已限制为仅正式代理发布，并补上回归测试。

## 使用方式

打开 Game Bar，在组件列表中打开「Claw 性能监控」，首次点击图钉固定。随后在工具箱的「性能显示」磁贴切换关／1—4 档；监控组件自身的菜单可调整字号、排版及识别纠正。

自定义监控窗口的位置与固定由 Game Bar 管理。原 RTSS 的屏幕锚点设置继续保留用于兼容方式；新组件通过 Game Bar 拖动定位。

## 尚未验证的边界

- RTSS 以管理员权限运行，当前执行会话无法结束它；已请求用户退出以补测。此次确认了新帧率来自独立 ETW 采集，尚未把“RTSS 进程完全退出”的场景记为实测通过。
- Game Bar 宿主未提供可单独定位的自动化窗口。已确认组件连接、目标信息及可见状态，视觉验证使用同一 XAML 页的预览入口；固定后收起 Game Bar 的最终显示和鼠标穿透仍需用户实机确认。
- 尚未逐款启动真实 Galgame、Game Pass/UWP 游戏、反作弊游戏，或验证真正独占全屏；不能以 Direct3D 测试程序代表这些场景。
- 已观察备用采集进程约 11 MB 工作集，但未完成真实游戏下的 CPU、整机功耗和续航对照测试。

## 构建与恢复

新增依赖通过 `tools/Prepare-NativeOsd.ps1` 准备，标准构建／打包已加入两个 Python 模块、固定版本采集器和许可证。采集助手、组件、游戏库分别使用现有的 `Build-TelemetryFix.ps1`、`Build-GameBarWidget.ps1`、`frontend/library-native/tools/Build-Msix.ps1` 构建。

`tools/Deploy-NativeOsd.py` 默认只做预检，`--apply` 才安装；后续本任务内更新使用已记录的模块哈希预检，支持只更新模块或组件。再次修改已安装的 MSIX 内容时，应先提升对应包版本号并更新部署目标。

原始安装前备份：`%LOCALAPPDATA%/ClawToolbox/repair-backups/native-osd-20261024-221143/`，包含旧后台模块、原始配置、Game Bar 0.4.29 与游戏库 0.1.101 的签名包。后续每次更新另有独立备份，最后一次模块更新记录在 `artifacts/native-osd/deployment.json`。回滚须正常停止后台后恢复模块与 `plugin.json`，并用旧签名包原位降级；保留用户 LocalState。
