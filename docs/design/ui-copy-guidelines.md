# 界面文案规范

适用于游戏库、控制中心及其子页、软件与单游戏设置、添加游戏、截图、首次设置、快捷设置和窗口切换。

- 默认只显示名称、值、状态和操作。不要添加问候、口号、装饰性副标题和填空式说明。
- 用分组、缩进、对齐、留白、图标及选中状态表达层级和关系。
- 不为每个标题、卡片、功能区或按钮配说明。相邻区域已经表达的信息不再重复。
- 保留影响操作、决策和错误恢复的信息：适用条件、生效时机、未保存状态、不可用原因、风险和确认。
- 删除可由标签与交互理解的低价值解释；确需保留的低频说明优先按需展示。关键限制不能只藏在 Tooltip 中。
- 同一组的共同生效条件集中显示一次；待生效的修改用状态显示。
- 列表行号不承担导航或操作含义时不显示。开关保持对齐，提示不挤占控制位置。
- 不显示开发阶段、实现方案或模仿来源来解释功能。功能不可用时说明其可用状态。
- 修改名称时同时检查以标题定位行的代码、验证入口和英文翻译。

每段可见文案都必须有明确的信息价值。能够通过设计表达的内容，不再用文字重复解释。

## 落到手柄界面上

- 只有图标的控件，焦点落上去时浮出名字（Popover），不常驻文字标签。
- 数值、单位、当前选项属于信息，可以直接显示。分区标题旁重复下方数值的摘要（比如「手动 · 25 W」）不加。
- 左栏图标已经标明分区，右侧不再重复写分区标题。
- 风险操作（关机、重启、恢复出厂、改固件）的确认文字直接显示，不藏进 Popover。
- 不主动加欢迎语、营销式修辞和教学段落；不为填补空白或营造氛围添加没有信息价值的文字。
