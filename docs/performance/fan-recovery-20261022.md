# 风扇高转调查与恢复判定修复（2026-10-22）

本机：Claw 8 EX AI+ CG3EM，EC `1T91EMS1.103`。独立风扇服务已从 1.0.3 更新为 1.0.4。界面未改，工具箱主程序与游戏库未重新部署。

## 原因与修复范围

用户的均衡曲线 `20 / 30 / 50 / 63 / 76 / 76` 保存和计算均正常。CPU 约 75°C 时，软件目标约 60–63%，但 EC 实际输出保持 94%，两扇约 5800 RPM。旧服务只核对曲线表和控制位，重新写表后就增加恢复成功计数，实际输出仍为 94% 也未报失败。

进一步离线核对本机原始 EC 镜像发现：最高温区降档还检查一个辅助温度。bank 3 的 `47AD -> 5976` 路径将 EC `F4` 与内部 `F38A + 温区` 比较；最高温区为 7，初始化后的 `F391` 为 60°C。此次高转期间辅助读数为 67°C，因此仅 CPU/EC 主温度降到 80°C 以下，仍不满足固件降档条件。辅助传感器对应的具体部件尚未确认，代码与文档不将它命名为 GPU、供电或外壳温度。

退出游戏冷却后，实读辅助温度降到 57–58°C，实际输出随之降回 60–62%，转速回到约 3600–4000 RPM。这个下降发生在固件冷却条件满足后，不能据此声称软件强制覆盖了高温保护。

最终修改：

- 冷却恢复同时检查 CPU、EC 主温度和已核对固件的辅助温度条件，连续满足十秒才尝试。
- 写表后要求两路实际输出连续三秒接近当前目标，才计为恢复成功。输出未恢复时保留错误和失败计数，至少间隔六十秒重试。
- 辅助温度仍高时报告等待固件冷却，不再虚报恢复成功，也不反复争抢控制。
- 自动恢复限定于已核对的 CG3EM / `1T91EMS1.103`；未知型号、固件或缺失辅助温度不执行此恢复。
- 保留当前输出字节、94% 保留档、温度阈值和其他控制位。76% 仍是用户曲线上限，高温保护可以越过该值。

排查时曾验证模式切换、当前输出同步和全速开关边沿；这些方式均不能在辅助温度仍高时解除 94%，未作为最终产品修复保留。测试中的临时设置均已恢复。

## 验证

- C# 回归通过：事务、故障回退、手动全速、实际输出确认、拒绝降速、短暂回落后再增压、重试间隔、辅助温度及传感器缺失。
- Python 风扇相关测试 25 项通过；修正了与现有温度平滑逻辑不一致的旧测试预期，未修改生产 Python 温控策略。
- 独立风扇服务与共用硬件层的 ClawPower 编译通过。
- 实机 76% 响应通过：两路实际输出均为 76%，两扇稳定在 4660–4706 RPM；恢复原曲线后的连续十次采样，实际输出 45–51%，两扇约 2857–3429 RPM，符合对应软件目标。
- 最终独立的六十秒只读观察通过：实际输出跟随目标，末段两扇约 3100–3180 RPM，无错误，配置文件保持不变。此观察未捕获新的高温保护解除事件，恢复确认分支由模拟故障回归覆盖。
- 所有原始三档曲线、均衡选择、关闭全速状态以及测试前功耗文件均保持原值。服务配置修订号因测试从 27 增至 33，设置内容未变；安装文件与最终构建哈希一致。见 `final-audit.json`。
- 原始镜像哈希、辅助阈值及对应指令离线检查通过，记录在 `diagnostics/fan-recovery-20261022/firmware-cooling-condition.json`。
- 实机响应和最终稳定观察的结果分别记录在 `response-verification.json`、`steady-state-verification.json`。稳定观察不等同于复现新版本的真实高温保护解除事件。

早期候选的实机验收失败报告保留在 `live-verification.json`；第一次响应测试在最后一次新目标写入时结束，保留于 `response-first-check.json`。后续响应测试改为等待连续稳定反馈后结束，不修改通过标准。

复现命令：`tools/Test-FanRecovery.ps1` 做无硬件写入的模拟回归；`tools/Verify-FanRecovery.py --steady-state` 做只读稳定观察；`tools/Test-FanRecoveryResponse.py` 会临时测试当前档的 76% 风量并在 finally 中恢复设置。

## 02:07 后游戏负载再次出现高转

用户反馈再次约 5800 RPM，本轮只读采样确认复现。02:07:53（北京时间），CPU 83°C、EC 主温度 87°C、辅助温度 59°C，软件目标仍为 76%，两路反馈切为 94%。之后风量反馈在 75–76% 与 94% 之间反复切换；连续二十五次新采样的两扇转速约 5581–5854 RPM，辅助温度 60–61°C。均衡原曲线和修订号 33 保持原值，全速关闭，无原厂 Auto 回退或外部覆盖修复事件。

此次证据支持温升再次触发固件增压、冷却条件未持续满足的判断。1.0.4 修复恢复判定、通过低温响应测试，不能据此认定已经解决真实游戏负载下的高转问题。另观察到短暂读到目标风量时状态会立即变为 normal，即使 RPM 仍高；当前不能将该瞬时状态视为已经恢复。

证据保存在 `diagnostics/fan-recovery-20261022/recurrence/episode.json` 和 `live-samples.json`。此次未更改风扇、功耗设置或运行中的游戏。
