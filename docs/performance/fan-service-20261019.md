# 独立风扇服务与即时设置更新

2026-10-19，本机 MSI Claw 8 EX AI+ CG3EM。已安装 `ClawFanService` 1.0.0（LocalSystem、Automatic），游戏库升级至 0.1.16.0。工具箱后台版本仍为 0.17.21，部署了服务客户端补丁；未部署此前放弃的 EC 曲线集成候选程序，也未改写固件。

## 用户操作

游戏库 → 性能 → 风扇：

- 选择静音、均衡或性能档，立即按当前 CPU 温度重新计算两只风扇的目标风量。
- 编辑当前档位的六个温度点；连续输入合并约 350 ms 后提交，服务立即重新计算。转子达到新转速需要机械响应时间。
- 服务协议也支持只修改非当前档位：保存配置，维持当前输出，切换到该档时使用新值。
- 选择“恢复原厂自动控制”会恢复备份曲线并退出自定义/全速控制；此选择也会保存。再次切换档位或开启全速会恢复自定义控制。

手动切换和当前曲线修改会重置防抖历史，立即应用。温度自然变化仍保留原来的上升约 6 秒、下降约 10 秒的防抖及高温分支。静音/均衡维持原有 76% 上限，性能最高 100%；不允许零风量。

## 保存和应用顺序

1. 原有 `save_power` 入口接收设置，校验三个档位、温度点数量、风量范围和控制方式。
2. 后台通过本机命名管道将风扇配置交给独立服务。客户端核对管道服务端 PID 是否与 Windows 服务管理器一致；管道限制本机授权用户、管理员和 SYSTEM。
3. 服务检查配置版本，拒绝覆盖已经变化的版本。所有更新与调速循环串行执行。
4. 当前档位改变时，读取新的 CPU 温度，计算风量，调用现有已验证的 WMI 写入路径，并检查两路表和控制位。其他温控字段保持不变。
5. 硬件应用成功后，原子替换服务配置文件。若写入、回读或持久化失败，尝试恢复旧档位；旧档位恢复失败时尝试释放到原厂自动控制。成功结果才返回前端。
6. 工具箱同步本地设置缓存；该缓存写入失败时，尝试将服务配置恢复到旧值。前端收到错误时显示保存失败，随后从服务刷新实际状态。

服务配置是风扇设置的权威来源，启动和恢复时不依赖工具箱缓存。通信中断时不能仅凭前端草稿判断实际状态，应重新读取服务状态。

## 进程和存储

- 服务程序：`C:\Program Files\ClawToolbox\FanService\ClawFanService.exe`。
- 服务配置：`C:\ProgramData\ClawToolbox\FanService\service.json`，含三档曲线、当前选择、配置版本和原厂曲线备份；仅管理员/SYSTEM 可写。
- 原有备份：`%LOCALAPPDATA%\ClawToolbox\data\fan-backup.json`，本次未覆盖。CPU/GPU 原厂均为 `60,64,68,74,80,84`。
- 工具箱缓存：`%LOCALAPPDATA%\ClawToolbox\data\power.json`。
- 原后台安装服务后仅读取状态和提交设置，不再自行调速，也不在退出时释放独立服务。服务不可用时报告错误，不回退成第二个写入者。
- 旧的直接 EC 固件诊断入口在服务模式下拒绝执行，避免和服务争用；共享硬件层也为安装后的服务保留写入所有权。

服务依赖 Winmgmt 和 PawnIO；配置自动启动和异常退出后 2/5/15 秒重启。正常停止会恢复原厂自动控制；强制结束进程依靠 Windows 服务恢复机制重新接管，不承诺强制结束瞬间就能执行恢复代码。

关机/休眠处理会尝试释放到原厂自动，唤醒处理重新读取温度并恢复保存的控制方式。进入 Windows 服务启动前仍由原厂固件负责。本轮没有自动重启、注销或让设备实际进入休眠。

## 维护入口

- `build.ps1` 完整构建包含服务及共享硬件层；`install.ps1` 会调用服务安装器。
- 仅更新服务/代理：`tools/Install-FanService.ps1`，需要 Windows 管理员提升，会备份并重启工具箱后台。
- `tools/Verify-FanService.py` 默认只读；加 `--exercise` 才切换档位、修改测试曲线和关闭后台，并在结束时恢复配置。
- `tools/Test-FanServiceLifecycle.ps1` 默认只读；加 `-Exercise` 才实际停止、启动和强制结束本服务。需要先编译只读探针 `tools/FanReadOnlyProbe.cs` 与共享硬件层。
