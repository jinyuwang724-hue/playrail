## 显示与采样

- 数字与硬件快照以 500ms 为周期；显示端锁存整组数字，同一周期内只推进曲线，不改 FPS、功耗、温度等数字。
- 曲线保留最多 10 秒、每条流最多 2048 点的逐帧历史，显示最近 5 秒。按本地单调时钟连续播放，缓冲默认 1.25 秒，根据批次间隔可增加到最多 2.5 秒；仅小幅修正播放速度以吸收时钟漂移，不修改帧时间 Y 值。不会把每次收到的最近 120 帧重新拉伸到整张图，也不因 FPS 数字变化重置曲线。
- 插帧数据优先采用 DisplayedTime。部分生成帧的 CPUStartTime／DisplayLatency 会出现无效的无符号下溢值，例如约 1.8446744e12 秒；过滤这些值，显示时间轴由真实显示间隔累积，避免曲线被推离视口。
- 交换链在有效期间保持选中，避免两条链平均 FPS 交错时反复换图；采集进程的保底期限从一分钟延长到一小时，正常关闭仍立即停止本软件自己的会话。
- 删除 App 和 Frame Count 显示区域；主 Frametime 区域加高到 124 逻辑像素，绘图区 100 像素，右侧每 10ms 一格，固定 0–50ms。超过范围的尖峰在顶部截断，Min/Max 仍显示真实值。保留用户要求的 Display Hz 区域。
- 缓存数值、布局、图表刻度和背景图层；文字按实际 Windows DPI 缓存栅格，保留像素对齐与描边。独立高精度计时器以 60Hz 调度曲线合成，接收线程只交付最新完整快照，避免界面消息排队。OSD 仍固定、鼠标穿透、置顶；二档背景仍铺满屏幕宽度，内容居中。
- Time 直接读取绘制进程的本地时间，按整秒更新，缓存键包含秒值；不依赖硬件采样、帧数据或半秒数值锁存，即使采样停止也继续走时。
- 权限后台保留原有硬件操作串行顺序，只有只读 ETW 队列使用独立通道。Python 按请求编号分发回应；原生双向管道两端使用异步句柄，避免读请求时阻塞另一个线程回写。已运行的 ETW 流在快速通道直接排空，不等待硬件／帧服务锁；AutoTDP 继续使用原始应用 FPS。

## 功耗统一

过去三个含义混在一起：工具箱／Game Bar 是 RAPL 芯片封装功耗；OSD CPU W 是 PP0 核心功耗；BATT W 是整机充放电功耗。系统页还有独立电量变化估算器，窗口和 OSD 不同，因此即使比较同一电池指标也会出现差异。

现在工具箱、Game Bar 和 OSD CPU W 都读取同一封装功耗快照，PP0 核心值只在后台作为 cpuCorePower 保留。工具箱及小组件标注「芯片功耗」，小组件增加说明。BATT 仍为整机电池功耗，它不应与芯片功耗或设置的 TDP 上限强行相等。

系统页、OSD 与小组件的电池提示共用同一份 batteryW、minutes、source 和 sampleId。传感器不报告功率时，采用最近最多 180 秒的电量变化估算，至少积累 15 秒；OSD 用 `~`、系统页／小组件提示用「估算」标记。预计续航根据同一功耗计算。

传感器统一在后台采样，界面读取直接返回缓存，不再每次启动风扇查询进程或额外进行一段功耗测量。Game Bar、工具箱性能页及系统页的电池快照读取周期改为 500ms；较慢的系统设置读取仍保留原周期。
