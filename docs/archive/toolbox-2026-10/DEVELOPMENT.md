## 使用

1. 在 Decky 打开 **Claw 按键切换**。
2. 开启 **Gaming 模式接管**；开关会保存，后续模式切换自动处理，桌面模式下 ClawTweaks 继续处理原映射。
3. 进入 Playhub Gaming 后，查看状态是否为 **Gaming：插件接管**。
4. 按两颗键，检查是否分别执行面板中选定的动作。本机现已按用户要求保存为 **MSI 打开右侧快捷面板、Xbox（原 Game Bar）键打开左侧主菜单**；也可以交换或关闭各自动作，更新插件会保留当前选择。
5. 返回 Playhub Desktop 后，状态应恢复为 **桌面：ClawTweaks 原映射**。

游戏内测试：从 Steam 启动游戏；MSI 打开右侧栏、Xbox 打开左侧栏，方向键和确认键应能操作菜单。再按同一颗前置键应关闭菜单，恢复操作游戏。通过 Steam 添加的非 Steam 游戏使用同样入口；未接入 Steam 的独立桌面程序不在当前路由范围。

发现双重动作、普通手柄不能操作或背键异常时，关闭插件开关并记录发生的模式和按键。已在当前 Playhub Gaming 环境完成实体键测试；WMI 通知本身不能抑制 Windows 的默认按键路径，其他版本或环境需要重新核对。

## 开发与打包

- `build.ps1`：使用 Windows 自带 .NET Framework 编译器，不要求 .NET SDK 或下载依赖。
- `test.ps1`：检查原生路由边界和 Steam 菜单适配器。
- `tests/backend_test.py`：插件设置校验测试，使用任意 Python 3 运行。
- `install.ps1`：复制本插件文件，升级前备份相同目标文件到本工作区 `artifacts`；相同内容不重复覆盖。
- `package.ps1`：将当前构建结果打包为 `artifacts/claw-button-router-0.2.4.zip`；不包含本机用户设置。
- `native/ClawRouter.cs`：事件等待、模式核对、ClawTweaks 正常退出与恢复、路由消息。
- `native/FirmwareShortcutFilter.cs`：Gaming 内置 Claw Win+G 来源识别、候选输入回放及附带 G 过滤。
- `plugin/main.py`：Decky 后端桥接；`plugin/frontend.js`：中文设置；`plugin/menu-router.js`：主页、原生覆盖窗口和 Playhub 焦点路由。编译脚本将前端与路由合并为单个 Decky 文件，不引入额外依赖。

改动原生后台时增加 `plugin/plugin.json` 的版本，避免覆盖正在运行的可执行文件。更新后通过 Decky 重载单个插件。

诊断读取状态可使用 `node tools/steam-probe.mjs --plugin-state`。它调用现有 Decky 路由，不重新创建插件连接。不要为检查状态再次调用 `deckyLoaderAPIInit.connect()`：当前 Decky 实现会替换该插件的事件监听表，导致实体按键动作无法得到响应确认。

`tools/restore-steam-overlay.js` 是本轮修复 0.2.1 污染当前 Steam 会话的工具，不随插件安装。仅在旧版已卸载并确认 `window.overlayStore` 原管理器存在时执行；插件正常运行使用分发列表，无需再次接管这个原生回调。
