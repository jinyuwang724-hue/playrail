## 添加非 Steam 游戏

在 Steam 大屏幕或 Playhub Gaming 中打开工具箱的 **添加游戏**，按以下流程操作：

1. **添加游戏** 默认展开，直接在 **浏览磁盘** 选择 C 盘、D 盘或其他磁盘，再点击 **选择游戏启动文件**。SD 卡上的游戏请选择它对应的盘符；插入 SD 卡后未显示时点击 **刷新磁盘列表**。使用 Decky 文件选择窗口选择游戏 `.exe`，或指向它的 Windows `.lnk` 快捷方式；首次 C 盘从 `C:/Game`、`C:/Games` 或用户目录打开，其他盘从根目录打开，后续分别记住每个盘选择过的目录。
2. 查看自动填写的 **游戏名称** 和 **启动文件**。名称可修改；快捷方式会解析到实际游戏程序，并沿用其启动参数。
3. 在 **游戏分类** 选择已有 Steam 集合（含收藏夹），或选择 **新建分类…** 并填写名称；不需要归类时保留 **不加入分类**。这里的分类是 Steam 库的集合，不移动游戏文件。
4. 点击 **添加并打开游戏库**。工具箱使用 Steam 当前客户端的原生快捷方式接口添加游戏，明确保存填写的游戏名称、等游戏库显示名称更新，再保存分类并打开游戏库的 **非 Steam 游戏** 标签页。完成时先关闭侧栏并解除之前浏览合集的页面上下文，再切换非 Steam 游戏标签；选择了分类时仍会保存游戏归类。不自动启动游戏。

打开工具箱、取消文件选择、修改名称及切换分类都不写入 Steam 游戏库；仅最终添加按钮提交。表单直接显示名称、文件和分类，移除原展开入口与返回按钮，添加成功后保持展开。表单跨文件选择窗口和选项窗口保留，沿用 0.6.2 的开关状态保留修复；初次挂载自动读取磁盘和分类，后续重挂载保留已填写内容。已有同一启动目标的入口在读取成功后会复用，并保存此次确认的名称，保留其参数和工作目录。新增入口自动使用程序所在目录作为工作目录；游戏特殊启动要求继续在 Steam 属性里设置。

分类或跳转未完成时保留已添加入口，显示 **继续完成并打开游戏库**，重试不会再次创建入口。新分类名称与已有分类相同时复用已有分类，不覆盖或清空它。后续编辑、启动、封面及移除沿用 Steam，工具箱不增加另一套游戏管理功能。

## 订阅恢复流程

1. 打开工具箱的 **网络代理** 区域，在 **订阅链接** 输入框粘贴 HTTP/HTTPS Clash 订阅链接，或 `clash://` 导入链接，点击 **添加订阅**。输入框无需连接步骤即可使用；成功添加后自动启用新订阅，同一链接已存在时选择已有订阅，避免重复创建。
2. 初始下载不使用系统代理；TUN 仍可能按当前规则处理连接。如果旧节点不可用导致初始添加失败，可先关闭 **系统代理** 和 **TUN 模式** 后再试。
3. 在 **当前节点** 中选择 AN 或 VL 等订阅专用节点，在上方开启 **系统代理**，选择 **规则** 或 **全局** 模式。全局模式时节点框显示为 **全局节点**。如订阅有单独的“订阅更新”代理组，也可用同一代理组和节点选择框将该组设为可用节点。
4. 点击 **刷新订阅**，通过运行中的本地代理下载并重新加载当前远程订阅。面板显示结果、订阅更新时间和当前载入的节点数量；成功后选择日常使用节点。服务端返回多少节点就显示多少，不以固定数量判定“完整”。

也可以手动选择 **当前节点**，开启 **系统代理**，选择规则或全局模式后刷新。全局模式的节点框自动切换为 **全局节点**，控制 GLOBAL 实际出口；返回规则模式后恢复此前的代理组。全局模式不会执行订阅中的游戏直连分流规则。模式和 TUN 开关调用 Verge 原生接口保存，面板显示核心实际状态；TUN 需 Clash 服务及相应权限支持。

当前订阅下拉框用于切换已导入订阅；远程订阅可以刷新，本地配置不支持网络更新。已有订阅无需再次添加，可以直接点击 **刷新订阅**。没有识别到专用节点时，可以使用普通节点下拉框，或选择包含专用节点的代理组。每次操作会重新读取实际状态；重新打开面板也能读取状态。

更新前将旧订阅内容和相关设置备份到工具箱设置目录下的 `subscription-backups`。下载或加载失败时，通过 Clash Verge 原生保存接口恢复旧订阅；如果连接中断、当前订阅被外部切换或恢复失败，保留备份并提示查看实际状态，不宣称恢复成功。不会删除已有订阅。订阅链接输入成功后清空，界面只显示来源域名，不显示 URL 中的令牌。

本机 Clash Verge 2.4.7 没有公开的订阅更新 HTTP 接口。第一次添加、刷新订阅或切换原生设置时，工具箱自动准备本机控制会话；必要时短暂重启已识别的 Clash Verge，网络可能中断片刻。安装或初次打开面板不会执行重启；输入格式错误也不触发准备。正常退出或重启 Clash Verge 后，下一次操作会自动重新准备，无需额外连接按钮。控制端口仅限 `127.0.0.1`，每次连接核对进程身份与端口归属，不向局域网开放，也不修改全局 WebView2 环境变量或用户订阅索引文件。应用原有全局扩展和游戏分流仍由 Clash Verge 生成配置。工具箱后台没有常驻订阅轮询。

## 反馈修复如何保持生效

工具箱承接 Playhub 发送的本机内置手柄导航反馈请求，并在自己的后端输出震动。安装目录内置包和已安装 Playhub 插件的两个修改入口已恢复为官方原版。Playhub 启动同步插件时，因此不会再删除工具箱中的兼容输出。

仍需要保留 Playhub 的 Decky 插件，并开启它原有的导航反馈设置。此次适配及参数比对基于 Playhub 2.1.0。

仅识别唯一的 MSI Claw 内置 `0DB0:1901` 手柄；外接型号和其他网络请求保持原有处理。只在可见的 Steam 大屏幕导航界面输出反馈；普通客户端、Steam 不在前台或 Steam 游戏运行时不输出兼容导航震动。返回桌面请求交给 Playhub 前先停振并撤销导航会话，延迟请求不能重新启动震动。关闭修复、前端卸载及后端停止时终止本模块震动。后端启动时清除被强制结束的前一个实例留下的马达状态；Steam 游戏运行时跳过该清理。没有新增驱动、虚拟手柄或常驻监视器，没有定时修改 Playhub 文件。

反馈修复关闭后，大屏幕导航返回 Playhub 原有输出，Playhub 自身的反馈开关仍决定是否发送反馈。兼容输出不可用时暂停反馈并显示状态，避免失败后启动另一条不受会话控制的震动。键盘导致的大屏幕界面反馈保留官方行为。
