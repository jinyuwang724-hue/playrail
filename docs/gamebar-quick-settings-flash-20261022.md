# 左快设键打开 Game Bar 闪现：0.17.55 路由修复

2026-10-22。本次基于当前已安装后台 0.17.55 的源码（452a7b5），只替换 ClawRouter-0.17.55.exe，不包含前端更新。部署后核对本机游戏库为 0.1.58.0、Game Bar 小组件为 0.4.20.0。原路由程序已与最新本地构建核对，SHA256 均为 954749427F43E728D6E698269126842B8E0D3E4760016BF389C9BA93298404B9。

## 实机根因

用户复测捕获到一次按压触发三次开关，Game Bar 进程未退出，Steam Game Bar 保护未启用：

| 本地时间 | 事件 |
| --- | --- |
| 14:55:44.929 | 实体 QS 发出原生 Win+G。 |
| 14:55:45.041 | Game Bar 输入重定向开启，第一次显示。 |
| 14:55:45.106–45.199 | 旧路由等待 160 ms 后误判没有硬件事件，以 Keyboard 来源补发一次 Win+G。 |
| 14:55:45.223 | MSI_Event 的 QS 通知到达，比原快捷键晚约 294 ms。 |
| 14:55:45.239–45.348 | 常规 QS 映射再补发一次 Win+G。 |
| 14:55:45.337 | Game Bar 输入重定向关闭。 |
| 14:55:45.509 | Game Bar 输入重定向再次开启。 |

这解释了“出现—消失—突然出现”。仅延长 160 ms 的等待还不够：即使去掉 Keyboard 补发，WMI 映射仍会把 Windows 已打开的 Game Bar 再切换一次。

## 修复

- 常规场景中，QS 配置为系统 Game Bar 或精确 Win+G 组合时，原快捷键直通，QS 的 WMI 通知只作记录，不再发送开关指令。Windows 处理一次按压的一次开关。
- Steam 大屏接管优先级保留。常规 Game Bar 映射不会使 Steam 内的快捷键过滤失效。
- 其他 QS 自定义映射继续经过原映射路径；其 Win+G 回放等待改为 700 ms，只与 QS 通知关联，场景切换或维护会取消旧回放。独立键盘快捷键仍可使用。
- 新增 native-gamebar 日志，能确认实体 QS 使用原生路径。
