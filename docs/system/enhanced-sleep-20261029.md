## 用户入口

系统 → 电池与电源 → 增强睡眠。初次默认关闭；打开后可单独选择睡眠时暂停游戏、暂停指纹识别。增强睡眠方案的 AC/DC 休眠倒计时均为 **172800 秒（48 小时）**，这是本次用户指定的行为。普通电源方案、原电源键动作和动画偏好保留。

关闭功能、正常唤醒、宿主退出或故障恢复时，恢复自己持有的资源。用户或第三方切换到另一个电源方案时，保留这个新选择。手动选择“休眠”仍直接进入 S4。

## 已实现的行为

- 唤醒原因 1/14/15/25/44 归入人为唤醒，空值及 0/20/29 保留未知，其余按无人唤醒处理。
- 明确无人唤醒延迟 2 秒尝试重新关屏；普通自动唤醒等待 20 秒确认，两者共用 30 秒限流。再次核对周期与用户活动，防止旧任务覆盖新的唤醒。
- 用户存在通知只有在已有唤醒证据后才释放会话；进入前已锁定时继续等待会话释放。仅关屏而未真正挂起的周期有恢复路径。
- 睡眠方案关闭唤醒定时器，启用 USB 选择性挂起，CPU 最低状态 AC/DC 为 5%/2%，PCIe ASPM 为 2，待机空闲 AC/DC 为 1800/300 秒，睡眠后 48 小时转休眠。
- 指纹仅处理一个正常的物理设备；禁用前落盘，确认问题码 22；唤醒先恢复认证能力，未恢复成功的记录继续保留。
- 暂停新版性能后台的帧、传感器、浮层及目标查询循环；输入引擎停止高频查询并释放旧式计时请求。虚拟手柄保留，唤醒不重新请求管理员权限。
- 动画电源键租约识别自己创建的睡眠方案，避免把正常切换当成外部冲突。
- 守护同时检查界面和睡眠工作线程。宿主卡住时核对进程身份，只结束自己的后台宿主，再恢复游戏及电源；设备恢复失败单独保留。异常后暂停增强睡眠，等待手动重新开启。
- 开机恢复分别尝试增强睡眠及电源键租约，其中一项失败不会阻止另一项恢复。

现代待机中没有批量禁用 USB、网卡或唤醒设备。联网偏好使用原版方案中的旧设置；现代 Windows 的实际联网行为仍由系统管理。这台机器只读检查为 S0 网络断开模式，并支持休眠。

- 自建宿主维持界面心跳但停止工作线程心跳，独立守护检测并结束这个测试宿主、恢复进程，留下故障暂停记录。
- 实际后台重新启动后，用户设置的哈希保持一致；控制接口确认增强睡眠可用、48 小时参数正确。验证期间增强睡眠保持关闭。
