# 游戏库被其他程序盖住时的唤出动画

当前可用版本为 **0.1.121**，用户已实测确认原场景「直接切回，已经不闪了」。0.1.119 未解决闪动；下文保留排查过程，最后一节为最终验证结果。

已基于当前安装的 0.1.118 完整源码更新为 0.1.119。用户反馈的场景是游戏库仍然打开、GPT 位于前台，再按 Claw 键唤回游戏库时画面抽搐。

## 修改

旧逻辑把「窗口仍可见但不在前台」也当成完整入场，先把根画面透明度置零，再 Show、Activate、置前和重试焦点。重复唤出也会新建动画；旧过渡的失效标记要到创建新动画时才更新，中间的窗口操作有机会处理旧完成回调。

现在根据真实窗口状态区分过渡：

- 真正隐藏、托盘或最小化后恢复：保留原有 520 ms 淡入、柔焦和微缩放。
- 窗口只是被其他程序盖住：根画面始终保持不透明，只做柔焦／1.02→1 的微缩放；不会先归零再出现。
- 已在前台：不重播；入场尚未完成时的重复请求沿用现有动画。
- 退场中重新唤出：保留当前画面位置反向继续，旧回调不能隐藏新状态。
- 入场中切到别的程序：取消该过渡并将后台画面整理为清晰、完全可见的稳定状态。

`ShortcutMotionState` 在 Show／焦点操作之前确定新的动画版本，完成回调必须持有当前版本才可清理效果或隐藏窗口。等待实际取得前台后才开始新动画；正常取得焦点后，60／180 ms 的定时器不再重复激活同一个窗口。已经显示的窗口不重复 Show，恢复流程也不再单独调用一次 Activate。

## 0.1.119 实测未解决，改为 0.1.120

用户反馈 0.1.119 在原场景仍会闪一下或抽搐。05:42 日志确认走的是 Refocus，且每次只有一次进入、正常完成，没有退场回调穿插；之前的“进出叠加”不是这次记录中的直接现象。该版本在窗口已经置前后才强制切到模糊／放大起始状态，并临时拆挂合成树，仍可能产生可见的首帧变化。

0.1.120 对真正已打开、仅被其他程序盖住的窗口只执行前台切换（日志 `mode=ForegroundOnly`），不重播透明度、缩放或柔焦，也不临时重挂特效层。窗口隐藏、托盘、最小化后的恢复仍使用 Reveal；进行中的主动收起被反向唤回仍保持 Reverse。被遮挡时遗留的入场会先失效并整理成稳定画面。

检查扩展为 18 项，新增对“被盖住后只切前台”及其取消旧入场回调的约束。以已安装 0.1.119 的匹配源码为基线，完整项目在 `artifacts/shortcut-foreground-fix/src/frontend/library-native`，构建已通过。该版本的原场景视觉结果仍需实测，不能将 0.1.119 的检查通过当作画面问题已经解决。

## 0.1.121：前台与置顶按一次交接

在上述不重播入场的基础上，继续调整原有窗口交接顺序：先通过既有 BringForward 取得前台，成功后才设为置顶；不再先用非激活的置顶把窗口摆到其他程序前面。SetTopmost 读取实际 WS_EX_TOPMOST 状态，值未变化时不重复 SetWindowPos，同时仍能适应全屏 presenter 改写窗口样式的情况。

0.1.120 为同一修复过程中的中间包，未作为视觉问题已解决的版本。最终候选为 0.1.121，完整匹配源码、签名包及安装回读位于 `artifacts/shortcut-window-fix`。18 项状态检查保持通过，前台交接的 Win32 绑定通过正式 NativeAOT 构建。游戏库原有偏好和电源动画设置、后台进程均保留；原场景是否已经平滑仍以用户视觉实测为准。

0.1.121 已安装，EXE SHA-256 为 `b0d283071508aca5ff2c305eb34828e267ba894410621bc8f86f569bf66b914d`。computer-use 已确认新版冷启动后的游戏库正常显示；启动遮罩 05:51:26.218 确认实际可见、05:51:27.728 正常释放。偏好哈希一致，Agent 25812 与电源动画控制器 23684 均保持运行。已请求只对原场景按一次 Claw 键验证是否仍闪动，暂不把稳定末帧当作动态问题通过。

## 最终实测通过

用户明确反馈「直接切回，已经不闪了」。06:11:12 和 06:11:22 两次从 GPT 窗口（HWND 132706）唤回，日志均为 `ForegroundOnly`，随后约 20 ms 内取得游戏库前台，没有重播进入动画。之后用户主动收起时仍正常播放 360 ms 退场；从托盘恢复的 520 ms Reveal 也正常完成。

本轮保留 0.1.121，不再调整动画或设置。原场景的视觉验证与用户反馈保存为 `artifacts/shortcut-window-fix/runtime-verification.json`。其他应用可能受到 Windows 前台权限限制的既有情况不在本次“GPT 在前”的通过结论中。
