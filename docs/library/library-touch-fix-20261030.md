# 返回图标与游戏卡片点击修复

以已安装的 0.1.183.0 对应源码为基础，构建 0.1.185.0。基线发布文件与安装目录中的可执行文件 SHA-256 一致：`463545fb8b057338d821f714c4b5a02aaa560039144aac1873ef8b3954780902`。

- 移除上次新增的左上角返回图标及点击区域。截图页筛选与布局图标、主页控制中心菜单继续使用各自的命中区域。
- 游戏库点中游戏卡片后，先清除分类栏的焦点，再聚焦并激活点中的卡片。点击原来聚焦的游戏卡片时也重新显示卡片焦点，避免操作继续落在“全部／Steam／本地”上。

原因是原先 `ClickAt` 找到了卡片，但没有清除 `_railFocused`；随后的 `Activate` 优先调用 `RailActivate`，因此再次执行了分类按钮。

自动回归调用实际 WinUI 卡片命中与激活路径，逐一检查三种分类，并覆盖点中“之前聚焦的卡片”和“另一张卡片”两种情况；同时检查控制中心、性能、显示、系统、软件、手柄及截图页不再提供新增的返回点击区域。每次只展开卡片，不启动游戏，不写入用户设置。共享触控逻辑另外单独回归，窗口中的点击使用相同 Pointer 事件路径；未注入物理触屏事件。

完整源码：`artifacts/library-touch-fix-184/src/frontend/library-native/`。相对 0.1.183.0 的差异：`tests/LibraryTouchFix/library-touch-fix.patch`；准备、验证入口分别为 `tools/Prepare-LibraryTouchFix.py` 和 `tools/Verify-LibraryTouchFix.py`。运行结果、安装与配置校验保存在 `artifacts/library-touch-fix-184/verification.json` 和 `installation.json`。

最新版快捷面板源码、其余界面源码、资源与附带组件按文件校验保持一致。根目录旧版前端未用于此次构建。

最终 49 项分类点击及返回区域检查、65 项共享触控回归全部通过；四份界面配置校验一致。实际窗口也完成了“全部／Steam／本地”三种分类的点击检查，对应卡片均正常展开。
