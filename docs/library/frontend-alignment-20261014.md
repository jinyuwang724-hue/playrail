## 必须对齐的差异

1. **代码入口**：主目录、最新分支、安装版本不同。先清点分支依赖并制定合并清单，避免直接从 main 构建安装导致回退。此轮未合并或部署。
2. **技术与尺寸**：旧 UI brief 仍要求 WebView2、560×1080；实际已改原生 XAML，近期提交调整到 464 宽、增加窗口高度。HTML 的 560／400 稿是参考，不应作为当前原生尺寸的唯一验收标准。
3. **功耗操作语义**：Steam 测试明确“未接管时，快捷磁贴进入功耗页，不直接接管”；Game Bar 磁贴从“系统控制”循环到“智能”时会启用接管。两端需要明确一致的状态含义，并决定是否保留不同操作入口。
4. **并发保存**：两端均持有功耗草稿并延迟提交。需要验证两个入口同时改不同字段时不会互相覆盖；必要时改成后台按字段更新或版本校验。当前只列风险，尚未复现丢失更新。
5. **按键与窗口共存**：现有路由仍在 Steam 接管期间启用 GameBarGuard。须明确“大屏幕内默认打开 Steam、其他场景打开 Game Bar”的规则，以及手动打开另一入口的处理方式，验证不会误关用户主动打开的组件。
6. **状态与错误**：统一已保存、执行中、实际生效、离线、失败的呈现；不能仅显示乐观更新值就当作硬件执行成功。核对断线重连与失败后读数恢复。
