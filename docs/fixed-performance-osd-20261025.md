# 固定位置性能显示（2026-10-25）

后续已按用户提供的模板重做四档，同时修复 Game Bar 关闭重开空白。当前状态见[模板与生命周期记录](osd-template-and-gamebar-lifecycle-20261025.md)，下文保留前一版记录。

按用户要求，保留旧 Game Bar Toolbox 的布局；「性能显示」单击循环为关闭 → 1 → 2 → 3 → 4 → 关闭。开启后立即启动独立固定悬浮窗，不需要打开、固定另一个 Game Bar 组件，也不以游戏识别结果决定可见性。未取得帧率时显示 --，硬件数据仍可显示。

档位参考 [Steam 官方性能显示说明](https://help.steampowered.com/en/faqs/view/3462-CD4C-36BD-5767)：

| 档位 | 内容 |
| --- | --- |
| 1 | FPS |
| 2 | FPS、帧时间、单帧最低／最高 FPS、曲线 |
| 3 | 二档内容 + CPU／GPU 占用 |
| 4 | 三档内容 + CPU 温度与频率、GPU 温度与显存、RAM 已用／总量、封装功耗 |

备用 ETW 数据标为「呈现 FPS」，不将其冒充游戏原生帧率或帧生成分解。最低／最高值由当前缓冲的有效帧间隔换算，曲线使用最多 120 个帧间隔；并非 Steam 的 90 秒历史图。无法读取的传感器显示 --。

位置通过游戏库「设置 → 性能显示 → 显示位置」调整，也可右键 Game Bar 原性能显示磁贴调整位置和字号。提供九个屏幕方位，锚定主显示器，边距 12 像素。显示窗无边框、不抢焦点、鼠标穿透，没有拖动入口。

`native/PerformanceOverlay.cs` 使用 WinForms/GDI+ 绘制；`claw_overlay.py` 由后台单独管理进程，通过 stdin 推送快照。关闭时关闭 stdin 并等待子进程退出，后台退出同样清理。子进程不接收后台凭据。

OSD 只采样当前前台程序，打开 Game Bar 时暂时保留之前的目标；不要求进程被归类为游戏，不使用逐游戏开关覆盖全局开关。原游戏识别仅供已有 AutoTDP 等功能继续使用，不控制本显示窗。现已取消 Monitor 扩展注册，仅保留旧 Toolbox 扩展。

已安装 Game Bar 0.4.35.0、游戏库 0.1.103.0，以及固定显示进程；功耗和风扇配置保留。窗口模式下实测单击 0→1→2→3→4→0、右键位置设置生效、关闭后显示进程退出。Direct3D11 验证程序收到约 64.65 呈现 FPS、120 个帧间隔。绘制与窗口样式检查覆盖四档和三种字号，共 12 种布局。真实独占全屏、HDR、多屏切换尚未验证。

Python 验证：原生监控 11 项、显示进程生命周期 2 项、PresentMon 解析 5 项、AutoTDP 20 项、后台协议 18 项，以及旧 OSD 配置回归。后台协议测试通过，但 Windows asyncio 在测试结束时仍输出套接字清理警告。最后将 OSD 留在关闭状态，下一次单击直接进入一档。
