# Auto 目标帧率功耗模式

2026-10-19：后台 0.17.19，Claw 游戏库 0.1.13，Game Bar 0.4.17。

## 入口与设置

游戏库 → 控制中心 → 性能 → 开启功耗接管 → 模式「Auto」。Intel 智能、按电源和手动模式仍保留。Steam 侧栏同样可选择 Auto；Game Bar 的功耗磁贴循环中加入 Auto，功耗目标磁贴在该模式下调整目标帧率，在 Intel 模式下选择 Intel 档位。

默认目标 60 FPS、持续功耗下限 12 W、插电上限 35 W、电池上限 25 W。目标可调 20–240 FPS；功耗可调 8–35 W，下限不能超过任一电源上限。短时上限 PL2 仍为控制器给出的 PL1 加用户保存的短时加成，界面中的 Auto 上限指 PL1。Auto 不设置固定 CPU 频率上限。

Auto 中的目标帧率用于功耗反馈，不是限帧开关，也不以插帧后的帧率为目标。若需要锁定帧率，使用游戏内限帧或独立限帧功能。

已有配置的 `mode: auto` 保持“按电源”原义；新模式为 `mode: autotdp`，新设置保存在 `autotdp` 中。升级不会改变当前模式，旧客户端未传入新设置时使用有效默认值。

## 算法与采样

实现参考 [Handheld Companion AutoTDP](https://github.com/Valkirie/HandheldCompanion/blob/a250b19a4b7e29dac3b383f2d1ac517d1af43e4e/HandheldCompanion/Managers/PerformanceManager.cs#L587) 的“帧率误差反馈、微分阻尼、稳定后探底”控制思路，使用独立代码与不同的响应参数、探底和保护规则。未复制、翻译或打包 HC 源码；不是官方 HC 组件，也不安装其驱动或手柄系统。HC 源码仍在桌面的独立审阅副本中，受其原始许可约束。

- 启动会话时以当前电源允许的持续上限开始。低于目标超过 max(1.5 FPS, 目标的 2.5%) 时，按相对帧率误差与变化速度增加功耗，每步 1–6 W。没有“实际耗电必须接近上限”的门槛，也没有禁止继续加功耗的学习上限。
- 目标附近稳定至少 6 秒才试探降低 1 W。试探后掉帧会恢复功耗，暂停继续探底 30 秒；这只限制再次降低，不限制因负载增加而提高功耗。
- 使用已有 PresentMon `appFps`，选择有效真实渲染帧率最高的交换链；不使用 RTSS 或插帧后的 `presentedFps` 驱动控制。
- 原生助手返回被跟踪的 PID 和查询窗口参数（1000 ms 平均窗口、1000 ms 偏移）。后台用发送请求的单调时间保守估算采样窗口；只有整个窗口晚于最近成功写入、且经过至少 3 秒，才允许下一次反馈调节。
- 不同 PID、目标、上下限、供电或 Windows 电源方案会重置历史。从控制中心返回游戏时，如果原 PID 仍存在则保持跟踪。
- 空样本、错误、错误 PID、非数值、零帧率、过期样本不参与决策；保持当前有界功耗，并展示等待原因。数据长时间中断后不把断开前的样本当作连续稳定记录。
- OSD 关闭时仍独立采样。ChatGPT、Codex、浏览器与工具箱进程被排除为前台游戏候选。

当前不会区分所有游戏瓶颈：持续达不到目标时可能用满设置的功耗上限；不能保证 CPU、引擎、温度或固件限制下增加功耗有效，也不直接强制提高 GPU 频率。

## 控制权与恢复

Auto 和 Intel 模式互斥，通过策略锁串行交接。Auto 写入前先保存功耗寄存器、各电源方案的四项 CPU 频率上限与原 Intel 状态到 `autotdp-session.json`，然后停用 Intel 自动策略、解除 CPU 限频。

退出 Auto、关闭接管或正常关闭后台时恢复会话原始设置。遇到多个 Windows 电源方案时分别恢复各方案已保存的频率上限，不切换当前方案；原生 `restore_freq` 仅对明确指定的已备份方案写入并回读验证。失败时保留交接记录，供重启重试。恢复不同方案的频率配置不会把旧方案的数值应用到当前方案。

功耗写入后回读检查。当活动 Auto 会话发现外部功耗改写，或 Intel 策略被外部打开时暂停并报告冲突，不反复争抢。解决冲突后重新选择模式即可重新接管。

调节状态、当前有效帧率、目标、上下限在性能页显示。诊断日志 `%LOCALAPPDATA%\ClawToolbox\data\autotdp-decisions.jsonl` 记录调节原因和实际读数，达到约 1 MB 后轮换，最多保留两份。

## 验证

- 18 项 Auto 测试：帧率异常、等待实际变更后的样本、稳定探底、低帧恢复、延迟场景、PID/目标/供电/电源方案重置、Auto/Intel/手动交接、失败回滚、后台重启与多方案恢复、外部改写、不支持 Intel 时使用 Auto，以及真实帧率与插帧读数分离。
- 原 Intel 14 项交接测试、原功耗后台检查、服务 14 项、代理 16 项及前端 6 项通过。代理测试仍伴随已有的 Windows asyncio 连接关闭警告，断言通过。
- 原生功耗助手、游戏库 NativeAOT/MSIX 与 Game Bar 签名包构建通过。游戏库仍有原手柄页的裁剪/AOT 警告与符号包工具缺失提示。
- 已安装版通过实际后台检查 Auto → Intel → Auto → 原模式：Auto 下四项 CPU 限频均为 0，Intel 关闭，PL1/PL2 实际写入并回读；Intel 下 Auto 会话已释放，控制权独立。最后恢复测试前的“按电源”模式、35 W/38 W、四项 2750 MHz，无错误、无遗留交接记录。
- 鼠标检查已安装的游戏库性能页：Auto 选择、目标/上下限、调节原因、真实帧率等待状态和 CPU 不限频说明正常显示；切回按电源后设置恢复。

没有启动鸣潮做游戏内帧率、帧时间或续航对照。以上验证证明接入和交接路径成立，不能作为鸣潮性能改善的实测结论。
